# Отчет об ошибках (Bug Report) для проекта BitString

## Дата: 2024

---

## BUG #1: Оператор файлового ввода не выбрасывает исключения при недоступности файла

**Статус:** Подтверждено  
**Приоритет:** Средний  
**Компонент:** BitStringIO, оператор `>>`

### Описание проблемы:
Оператор `operator>>(std::istream& is, BitStringIO& bitStr)` не выбрасывает исключение при попытке чтения из несуществующего или недоступного файла. Вместо этого поток молча устанавливает флаг `failbit`, что может привести к незаметным ошибкам в коде пользователя.

### Местоположение:
Файл: `Source.cpp`, строки 103-108

```cpp
std::istream& operator>>(std::istream& is, BitStringIO& bitStr) {
    std::string input;
    is >> input;
    bitStr.setFromString(input);
    return is;
}
```

### Воспроизведение:
```cpp
BitString bs;
std::ifstream badFile("/nonexistent/file.txt");
badFile >> bs;  // Исключение НЕ выбрасывается!
// bs остается неизменным, но пользователь может не заметить ошибку
```

### Фактическое поведение:
- Исключение не выбрасывается
- Поток устанавливает `failbit`
- Объект `BitString` остается в предыдущем состоянии

### Ожидаемое поведение:
- Должно выбрасываться исключение (например, `std::runtime_error`) при неудачной операции чтения
- ИЛИ документировать необходимость явной проверки состояния потока

### Рекомендуемое исправление:
```cpp
std::istream& operator>>(std::istream& is, BitStringIO& bitStr) {
    std::string input;
    if (!(is >> input)) {
        throw std::runtime_error("Failed to read from stream");
    }
    bitStr.setFromString(input);
    return is;
}
```

## BUG #2: Оператор файлового вывода не выбрасывает исключения при невозможности записи

**Статус:** Подтверждено  
**Приоритет:** Средний  
**Компонент:** BitStringIO, оператор `<<`

### Описание проблемы:
Оператор `operator<<(std::ostream& os, const BitStringIO& bitStr)` не проверяет состояние потока после записи и не выбрасывает исключение при ошибке вывода.

### Местоположение:
Файл: `Source.cpp`, строки 96-101

```cpp
std::ostream& operator<<(std::ostream& os, const BitStringIO& bitStr) {
    for (int i = 0; i < bitStr.getSize(); i++) {
        os << bitStr.getChar(i);
    }
    return os;
}
```

### Воспроизведение:
```cpp
BitString bs("10101010");
std::ofstream badFile("/nonexistent/path/output.txt");
badFile << bs;  // Исключение НЕ выбрасывается!
// Пользователь не узнает об ошибке записи
```

### Фактическое поведение:
- Исключение не выбрасывается
- Поток устанавливает `failbit`
- Данные теряются без уведомления

### Ожидаемое поведение:
- Должно выбрасываться исключение при неудачной операции записи

### Рекомендуемое исправление:
```cpp
std::ostream& operator<<(std::ostream& os, const BitStringIO& bitStr) {
    for (int i = 0; i < bitStr.getSize(); i++) {
        os << bitStr.getChar(i);
        if (!os.good()) {
            throw std::runtime_error("Failed to write to stream");
        }
    }
    return os;
}
```

## BUG #3: Оператор присвоения выбрасывает исключение при разных размерах

**Статус:** Подтверждено  
**Приоритет:** Низкий (так как все BitString имеют фиксированный размер 8)  
**Компонент:** BitString, оператор `=`

### Описание проблемы:
Оператор присвоения `operator=(const BitString& other)` выбрасывает исключение `std::invalid_argument` если размеры операндов не совпадают. Это может быть неожиданным поведением для оператора присвоения.

### Местоположение:
Файл: `Source.cpp`, строки 127-138

```cpp
BitString& BitString::operator=(const BitString& other) {
    if (this == &other) return *this;
    
    if (getSize() != other.getSize()) {
        throw std::invalid_argument("BitString sizes must be equal for assignment.");
    }
    
    for (int i = 0; i < getSize(); i++) {
        getChar(i) = other.getChar(i);
    }
    return *this;
}
```

### Воспроизведение:
```cpp
// В текущей реализации все BitString имеют размер 8,
// поэтому воспроизвести можно только при изменении API
BitString bs1("11001100");
BitString bs2("00000000");
bs2 = bs1;  // Работает, так как размеры равны
```

### Фактическое поведение:
- При разных размерах выбрасывается `std::invalid_argument`

### Ожидаемое поведение:
Варианты:
1. Изменить поведение на автоматическое изменение размера
2. Удалить проверку размеров (если они всегда одинаковы)
3. Документировать это ограничение

### Примечание:
В текущей реализации все объекты BitString имеют фиксированный размер 8, поэтому эта проверка избыточна, но полезна для будущих расширений.

## BUG #4: Конструктор копирования создает поверхностную копию указателя

**Статус:** Требует проверки  
**Приоритет:** Высокий  
**Компонент:** BitStringBase, конструктор копирования

### Описание проблемы:
Конструктор копирования выполняет глубокое копирование данных, что корректно. Однако необходимо убедиться, что деструктор корректно освобождает память для всех классов наследников.

### Местоположение:
Файл: `Source.cpp`, строки 18-23

```cpp
BitStringBase::BitStringBase(const BitStringBase& other) : size(other.size) {
    bs = new char[size];
    for (int i = 0; i < size; i++) {
        bs[i] = other.bs[i];
    }
}
```

### Текущее состояние:
Глубокое копирование реализовано корректно. Деструктор также корректно освобождает память.

### Рекомендация:
Добавить тесты на проверку отсутствия утечек памяти с использованием инструментов типа Valgrind.

## Рекомендации по улучшению

1. **Добавить обработку исключений в файловые операции** - операторы `<<` и `>>` должны явно обрабатывать ошибки ввода/вывода

2. **Добавить методы для работы с файлами по имени** - вместо работы с потоками, предоставить методы:
   ```cpp
   void loadFromFile(const std::string& filename);
   void saveToFile(const std::string& filename) const;
   ```

3. **Документировать ограничения** - явно указать что размер BitString фиксирован (8 бит)

4. **Добавить поддержку изменяемого размера** - рассмотреть возможность изменения размера через конструктор

5. **Добавить unit-тесты для проверки утечек памяти** - использовать Valgrind или AddressSanitizer
